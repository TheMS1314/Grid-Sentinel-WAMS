# Phase 48: External MITM Workbook-Holdout Audit (26 October 2026)

## Source and protocol boundaries

Mohamed Faisal Elrawy, Lenos Hadjidemetriou, Christos Laoudias, Maria K. Michael, *Detecting and classifying man-in-the-middle attacks in the private area network of smart grids*, Sustainable Energy, Grids and Networks (2023). Public dataset: https://zenodo.org/records/8375657. Download the published `MITM Attack Datasets_V1.zip`; expected MD5 `8ceb392f6a69086635159ff5bd0fff17`. The release excludes the raw third-party source. Its readme describes real-life Modbus A-H, simulated MMS D1-D4 and simulated Modbus D5-D8, using ARP poisoning and port stealing.

Each workbook contains five flow features (IRTT, TTOC, MITR, MATR, NROC), an ARP poisoning indicator and a label: 1 normal; 1000 controller MITM, 2000 router MITM, 500 two-way MITM and, for D4/D8, 50. All non-1 labels count as MITM in **binary** evaluation. This differs materially from the existing Data4Cyber four-lane packet/meter/tariff schema. **The results below assess a newly fitted exploratory flow-feature baseline, NOT the previously frozen Grid Sentinel four-lane model.**

## Holdout design

- Three separate evaluations: real Modbus A-H (5,583 rows), simulated MMS D1-D4 (2,804 rows), simulated Modbus D5-D8 (2,801 rows).
- Leave one *entire workbook* out in each fold. Train on all other workbooks in the same protocol/domain group. No random row splitting or mixing simulation into real laboratory training.
- Fixed RF hyperparameters `n_estimators=300`, `min_samples_leaf=5`, `class_weight=balanced`, `random_state=42`, median imputation. Compare (i) original five flow features (ii) flow+ARP indicator (iii) zero-training ARP-only rule. These were examined on the same test workbooks: **exploratory model comparison, not an untouched final holdout**.
- The counts and per-workbook confusion matrices are recorded in `SmartGrid_Phase48_External_MITM_Holdout_2026-10-26.json` and regenerated by `external_mitm_experiment_holdout.py` from the publisher's archive.

## Why the high scores must not be overstated

1. Each sample is an already engineered flow-feature row, **not a verified timestamp-aligned live packet/meter observation**. The original four-lane policy cannot be evaluated directly from these columns.
2. Workbooks may originate from the same experimental apparatus, conditions and feature-extraction process. Whole-workbook holdout reduces ordinary row-level leakage but **does not establish independent-site generalization**.
3. The ARP indicator may derive from experiment/instrumentation information; treat it as a privileged feature until provenance is established, not guaranteed passive-sensor observability. Flow-only numbers are therefore the more conservative headline.
4. Cross-protocol models are separately trained. No claim of a universal model handling MMS and Modbus without adaptation.
5. Precision is measured per labeled feature row, **not** operational false alarms/day or malicious event coverage. No latency, calibration, open-set detection, deployment or adversarial robustness claim.
6. Class 50 semantics are not explained by the header; binary attack mapping follows the dataset's non-normal encoding and must be confirmed with the authors before multiclass interpretation.

## Next gating work

Obtain untouched independent plant captures or matched packet+meter+tariff traces, prove feature availability and timing, precommit any policy and thresholds, then score malicious-event recall, per-family recall, benign false alerts/day, drift and collection failures. Private Docker host acceptance and real utility tariff signer trust remain unverified. **Do not upgrade project readiness to 90% based solely on this post-hoc external-feature baseline.**
